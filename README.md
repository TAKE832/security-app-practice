## 概要

COACHTECH 教材 Tutorial 10-6「Webセキュリティ ハンズオン演習」で作成した成果物です。
（CSRF対策のための@csrfディレクティブと、XSS対策の、{{ }}を使ったBladeの自動エスケープ機能を学習し、動作の確認も行いました。）

## 使用技術

- PHP 8.x
- Laravel 10.x
- CSRF 保護（'@csrf'）、XSS 対策（Blade の自動エスケープ）

## 学んだこと

- SQLインジェクションに対し、Laravelに備わっているプリペアドステートメントという機能を使うことが重要であることが分かった。その機能は、SQL文に直接ユーザーからのデータを埋め込まないことで、シングルクォートなどの特殊文字をエスケープする方法であることを理解した。
- CSRF攻撃や、SQLインジェクション、XSS攻撃など、Webアプリケーションには、個人情報等を危険にさらす要因が多くあることを学んだ。アプリケーションを制作する上で、ユーザー側の情報を扱っていることを念頭に置き、様々な攻撃に対する対処法を設定しておくことが重要であると思った。
- practice と sample を比較すると、'name'カラムのバリデーションルールの文字数制限を行っていないことに気づいた。文字数の制限をしておくことは、サーバー側への負担を減らすことに繋がると思ったので、今後は実際の開発を意識した必要最低限のルール設定についても考えながらコードを書くようにしたい。

## 詰まったポイントと解決方法

- フォームを送信するボタンを押しても動作しない問題が発生した。改めてform.blade.phpのコードを読み直していると、自分が誤操作をした際に、(</form>)を意図しない場所に書いていることに気づいた。それを消去することで、問題が解決した。コードを読む際は誤操作をして、機能を崩さないよう細心の注意を払って作業したい。
- モデルを使わずにデータを送る方法が分からなかった。過去の教材を読み直し、バリデーション済みのデータを送る方法や、モデルを使わないデータの送信を再確認し、データを送ることができるようになった。

## 動作確認

（http://localhost/contact） にアクセスし、フォームの表示や送信、入力内容の表示が問題なく行われていることを確認した。また、@csrfを削除すると419エラーが発生することや、<script>が実行されないこと、それらをHTMLソースを使って確認するなども行った。
